This week's project is a 3D platformer for an andriod device. I create a simple level called: Coconut Collector, playing as a huminoid shark on a collection of tropical islands. Using low poly assets to help lessen the load on graphic quality.

The player can move, jump and double jump. The camera moves with the player so there is no idependant controls for the camera so the two main touchscreen cotrols are movement and jump. The mechanic in this game is the collecting of coconuts which are scattered across all of the islands if the player can get to them via the bridges of floating stones or varing sizes.

Using anchor points in the UI and automatic text sizes to ensure the controls and menu are accessible to the different sizes of mobile screen.

Within the Unity simulator I could see how the different screen shapes and sizes affected the UI and using the mobile graphic asset as default.

Using the profiler the framerate keeps steady above 60FPS and nothings is being spiked for any long periods of time.

Building my project and transfering it to my phone, my phone is an andriod (Motorola). Downloading and opening my project my UI fit perfectly and orginsied on screen, playing the game apart from a short wait time for the application to open, around 15 seconds, the game run smoothly and the graphics were of good resolution. At no point did the game lag or have trouble.

The only notisible different between in editor on my PC and testing on my phone is the sensivitvity of the controls. Playing on my phone the touchscreen controlls for movement were much to sensitive and the camera moved just as fast with any slight change of my finger which caused difficulty in smooth movement, where as on PC, using my keybaord it was easier to control the character and camera.

Without testing the touchscreen controls on my phone I wouldn't have notice how hard it was to move the player character on mobile.
